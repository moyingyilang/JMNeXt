# 多语言

界面文案走 Android 自己的资源机制，没有引第三方 i18n 库。

## 文件

```
app/src/main/res/values/strings.xml          默认，简体
app/src/main/res/values-zh-rTW/strings.xml   繁体
```

键一一对应，缺键回落默认。要加英语就新建 `values-en/strings.xml`，代码一行不用改。

## 写法上的几条

- 格式化用 `%1$s` / `%2$d`，两份文件占位符顺序必须一致
- 多行文本写 `\n`，直接换行会被折成空格
- Composable 里用 `stringResource`，协程 / ViewModel / 回调里用 `ctx.getString`——后者没有 Composable 上下文
- ViewModel 里产生的提示（比如详情页的动作结果）用一对字段：`xxx`（服务端原话，String）和 `xxxRes`（本地文案，资源 id），界面优先取资源

## 生成

从简体批量生成任意一门语言：

```
./scripts/i18n-gen.sh zh-TW s2twp    # 台湾正体
./scripts/i18n-gen.sh zh-HK s2hk    # 香港正体
./scripts/i18n-gen.sh en skeleton   # 英文骨架，值是 key 本身，等人工填
./scripts/i18n-tw.sh                # 等价于第一行
```

OpenCC 的配置名直接传；`skeleton` 生成占位骨架。每门语言的用词覆盖放在
`i18n/overrides/<语言代码>.sed`，转换完自动应用（例如把 OpenCC 的「遮蔽」改成「封鎖」）。

## 加一门语言要改哪几处

1. 在 `i18n/overrides/<代码>.sed` 放用词覆盖（可选，但繁中这类一定要有，OpenCC 的通用译法不对路）
2. 跑 `./scripts/i18n-gen.sh <代码> <配置>` 生成 `values-<代码>/strings.xml`
3. 跑 `./scripts/i18n-check.sh`，确认键数与简中一致
4. 需要的话在设备上验一眼：`cmd locale set-app-locales com.jmnext.debug --locales <代码>`

英文这类没法机翻的，先 `./scripts/i18n-gen.sh en skeleton` 出骨架，值是 key 本身，再逐条填。

## 检查

```
./scripts/i18n-check.sh
```

比对两个文件的键集合，再统计编译产物里的 `zh-rTW` 条目。键对不上会列出来，退出非零。

## 已知例外

- `ui/Messages.kt` 的「未知错误」：异常 message 为空时的兜底，调用点都在 ViewModel 里没有 Context，
  所以保留中文常量。它只在极少数没有 message 的异常上出现
- `ui/LocalRepository.kt`、`ui/theme/Theme.kt`、`ThemeStyle.kt` 里的 `error(...)`：开发者断言，不面向用户
- 数据层（shared 模块）的 `ComicRenderMode.label/hint` 仍是中文，界面层已经用 when 映射到资源；
  shared 不引 Android 依赖，这个映射是刻意的

## 现在的边界

- 只有系统语言 / 应用语言生效，**没有应用内切换**。Android 13 起可以在系统设置里单独改本应用语言
- 分类名、作品名、标签、章节名来自服务端，不归这套资源管；服务端会按 `lang` 参数返回繁体
- 繁体译名参照官方 2.1.13 的字典（`i18n/upstream/`），个别词按台湾用语改过，没有请母语者校对
- 还没接的：评论、收藏/历史/追更、标签收藏几处的动作结果提示（都在 ViewModel 里，需要同样的 `xxxRes` 改造）
