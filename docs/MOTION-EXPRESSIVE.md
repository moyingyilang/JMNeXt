# 动效设计：从「一堆曲线」到一套可判定的语言

> 这是 1.8.x 之前就提过、一直没真正做成的那件事。本文是**设计契约**，不是灵感清单：
> 每一条都要能回答「解决什么感知问题」，并且**可判定**（写成单测或帧率指标，而不是"看着还行"）。

## 零、先厘清一个失败尝试（如实记录）

我尝试直接读本机 material3 库里的 `MotionScheme`（`expressive()` / `standard()` 的 spring 参数）作为基准，
结果是 **`MotionScheme` 在当前版本是 `internal`**，测试代码编译不过：

```
e: Cannot access 'interface MotionScheme': it is internal in file.
e: Cannot access 'fun expressive(): MotionScheme': it is internal in 'MotionScheme.Companion'.
```

结论有两条，都很重要：

1. **不要**把动效 token 建立在库的未公开实现上 —— 版本一动就散；
2. 所以 token 由**我们自己定义**（现有 `JmEasing` 已经是这个路子），
   权威性靠**帧率与观感实测**建立，而不是靠"抄官方数值"。

## 一、三条判断标准（一切动效先过这三关）

| 标准 | 含义 | 不满足时的处理 |
| --- | --- | --- |
| **可中断** | 动画进行中用户再次输入，状态必须能从中途接上（而不是排队或跳变） | 用 `Animatable`/`animateTo` 而不是重启动画 |
| **有因果** | 元素从"它来的方向"进入、回到"它去的地方"退出（空间连续性） | 检查位移起点/终点是否与触发控件的位置关系一致 |
| **不抢戏** | 每屏同一时刻**只有一处**主运动；其余用淡入/微位移 | 删掉次要运动 |

## 二、token 表（本项目口径）

时间单位 ms；曲线用 cubic-bezier 表述，便于两端（Compose / Qt）复用同一组数字。

| 交互 | 时长 | 曲线 | 位移/缩放 | 解决什么 |
| --- | --- | --- | --- | --- |
| 按压反馈 | 90 | `standard` (0.33,0,0.67,1) | 缩放 0.97 → 1.0 | 指尖"按下去了"的即时确认（<100ms 才像触觉） |
| 列表项进入 | 220 | `fluent` (0.16,1,0.3,1) | Y +12dp → 0，透明度 0 → 1 | 内容"长出来"而不是"跳出来" |
| 列表项移除 | 160 | `inCubic` (0.55,0.055,0.675,0.19) | 高度 → 0 + 透明度 → 0 | 退出要**比进入快**，否则显拖沓 |
| 前进转场 | 300 | `decel` (0.1,0.9,0.2,1) | 新页 X 100% → 0，旧页 0 → −25% | 深度隐喻：新页从右推入 |
| 返回转场 | 260 | `outCubic` (0.215,0.61,0.355,1) | 反向，且**比前进快** | 返回是"撤销"，用户已知道要去哪 |
| 共享元素（hero） | 320 | `emphasized` 近似 (0.2,0,0,1) | 位置+尺寸连续插值 | 让人相信"这就是同一张图" |
| 底部栏展开/收起 | 240 / 200 | `decel` / `inCubic` | 高度 + 内容淡入（**错开 40ms**） | 先给容器、再给内容，避免内容被裁切 |
| 对话框 | 进入 200 / 退出 150 | `decel` / `inCubic` | 缩放 0.92 → 1 + 遮罩 0 → 0.4 | 对话框是"聚焦"，不是"飞入" |
| 阅读器工具栏 | 显 180 / 隐 150 | `standard` | 顶/底栏 Y ±100% | 沉浸阅读时工具栏必须**迅速让位** |
| 加载态 | 骨架 1200 循环 | 线性（唯一允许线性处） | 扫光位移 | 线性=进度未知，反而是正确语义 |
| 错误态 | 200 + 抖动 3 次 | `outCubic` | X ±4dp 衰减 | 抖动只在"有输入被拒"时用，且必须衰减 |

**硬约束（可写成单测）**：

1. 所有时长必须在 `[90, 600]` 区间；退出类时长必须 ≤ 对应进入类时长；
2. 除加载态外，**不允许线性曲线**；
3. 同一屏的入场动画必须共享同一曲线族（不允许一屏三套缓动）。

## 三、与现状的差距（依据当前代码）

现有 `ui/theme/Theme.kt` 的 `JmEasing` 已有 7 条曲线：`standard`、`decel`、`fluent`、`outCubic`、`inCubic`、
`inOutQuad`、`hyperOS`(+`hyperOSOut`)。差距在**系统层面**，不在曲线数量：

| 差距 | 表现 |
| --- | --- |
| ~~没有"交互 → token"的映射表~~（**更正**：多数已是 `motion.base/enter/exit/fast`；真正缺的是阅读器工具栏的 5 处**未指定 spec**，已接 `readerBarsIn/Out`；随机转场的 600ms 旋转仍待处理） | — |
| 缺退出语义 | 多数动画只有进入，退出用同一个 spec（导致"退出和进入一样慢"） |
| ~~缺共享元素~~（**更正**：`jmSharedElement` + `SharedTransitionLayout` 早已接线，只是曲线取的是 `motion.base/enter`；已改用 `hero` token 的 emphasized 曲线） | — |
| 缺 reduce-motion 降级 | 系统关闭动画 / 无障碍"减少动态"时没有统一退化路径 |
| 没有帧率证据 | 动效"好不好看"目前全靠肉眼，没有掉帧数据 |

## 四、落地步骤（每步可独立验收）

1. **token 落地**：`ui/theme/Motion.kt` 定义 `JmMotion`（上表的类型安全映射），加单测覆盖上面三条硬约束；
2. **替换硬编码**：全局搜 `tween(` / `spring(`，逐处改为按交互取 token；
3. **退出语义**：给 `AnimatedVisibility` 的 `exit` 分支统一用"更快"的 token；
4. **共享元素**：`SharedTransitionLayout` 接详情页 hero（图片 + 标题）；
5. **reduce-motion**：读系统动画缩放（`Settings.Global.ANIMATOR_DURATION_SCALE`）→ 为 0 时退化为纯淡入（时长 120ms）；
6. **帧率验证**：`dumpsys gfxinfo <pkg>` 或 `FrameMetrics` 记录关键路径的 90/95 分位；目标：列表滚动与页面转场 **95 分位 ≤ 16.7ms**；
7. **桌面端对齐**：`desktop/Motion.kt` 用同一组时长/曲线数字（Qt 组件那边同样按此表）。

## 五、验证方式（明确区分）

- **可自动验证**：token 映射正确性、三条硬约束、reduce-motion 降级分支；
- **需真机/目视**：观感是否"更美观"（这是主观项，最终由用户确认）；
- **需测量**：帧率分位数（我可以在设备上用 `dumpsys gfxinfo` 取，但要先装上带改动的包）。

## 六、不做什么

- 不做"每个控件都加动画"：没有因果关系的运动只会让界面显得廉价；
- 不做弹跳（bounce/overshoot）除非表达"越界后回弹"这一物理含义；
- 不为了动效牺牲启动时间或首帧。

## 七、帧率基线（2026-10-25，真机实测）

设备：本机（aarch64 Android 15/16，具体型号未记）。构建：`app-full-debug.apk`（2.1.9 之后、动效 token 接入版）。
采集方式：`pm install -r` 覆盖安装 → `am force-stop` + `am start` 冷启动 → 等 8s → `dumpsys gfxinfo com.jmnext reset`
→ 5 次滑动 + 1 次点击 → `dumpsys gfxinfo`。

| 指标 | 数值 |
| --- | --- |
| Number Missed Vsync | **0** |
| Number Slow UI thread | **0** |
| Number Slow issue draw commands | **0** |
| 帧耗时分布 | 集中在 7–9ms（7ms 206 帧、8ms 272 帧、9ms 308 帧），共约 1122 帧 |
| 50th gpu percentile | 6ms |
| 90th gpu percentile | **7ms** |
| 95th gpu percentile | **10ms** |

**判定**：95 分位 10ms < 16.7ms（60fps 预算），当前动效在**滚动与点击路径上没有掉帧**。
这条基线的作用是：以后任何动效改动都要再测一次并与之对比，**不允许靠"看起来还行"结案**。

**未覆盖的路径**（下一轮补测）：页面前进/返回转场、hero 共享元素、阅读器工具栏显隐、底部栏展开 —— 这些需要逐项
`gfxinfo reset` + 单次操作分别采集，滚动路径的基线不能代表它们。
