# 桌面端观感对齐 Android：差距清单

目的：把「桌面端差点什么」写成可核对的条目，而不是凭感觉调。

## 一、已对齐的部分

- 设计语言的来源一致：两端都按博客的 Fluent × MIUI 基调做（Android 的 `ui/theme/Tokens.kt` 注释里写明逐项移植自 `global.css`）
- 字体族处理一致：汉字都走确定含中日韩字形的字体族，避免日式字形与方框
- 深浅色优先级一致：用户显式选过就用用户的，否则跟随系统
- 动效结构一致：桌面 `Motion.kt` 的 120 / 220 / 280ms 与 Android 的 120 / 200 / 320ms 同量级

## 二、差距

### 1. 圆角不是一套

| 端 | 圆角 |
| --- | --- |
| Android | 随风格变：WindowGlass `8/12`、FlatBlur `16/24`、Miuix `16/28`、Material `20/28`（lg/xl） |
| 桌面 | 全局固定 `8/12/18`，卡片另写死 `10.dp` |

后果：桌面端切换风格时卡片圆角几乎不变，只有面板透明度在动，这是"风格切了但没切"的主要来源。

### 2. 字号层级不是一套

| 端 | 页标题 / 区块标题 / 正文 / 说明 |
| --- | --- |
| Android | 由每种风格的 `TypeScale` 决定 |
| 桌面 | 写死 24 / 17 / 15 / 13.6 / 12.5 sp |

### 3. 表面材质只做了透明度

Android 的 `SurfaceSpec` 有六个维度：填充透明度倍数、强调色薄染、发丝描边、上缘高光、背景饱和度、噪点颗粒，另有阴影阶梯与按压缩放。

桌面的 `GlassStyle` 只有 `surfaceAlpha` 与 `corner` 两个参数，加上可选的壁纸模糊。没有发丝描边、没有高光、没有噪点、没有阴影阶梯。

### 4. 组件缺失

| Android 组件 | 桌面现状 |
| --- | --- |
| `SectionTitle` / `SectionHeader`（去掉服务端混进标题的「→」提示、右侧动作槽） | 各屏自己写 `Text(..., titleMedium)`，没有统一去掉箭头 |
| `ComicCard`（3:4 封面、按风格的 `Radius.lg`、更新角标） | 自己实现，圆角写死 10dp |
| `StateBox`（空/错/加载三态） | 各屏自己拼 Text |
| `LoadMoreFooter` | 各屏自己拼按钮 |
| `GlassTopBar` | 桌面没有顶栏，用侧栏 |
| `FloatingBottomBar` | 桌面用侧栏，不需要 |

### 5. 结构差异（不是缺陷，但影响观感）

Android 是「顶栏 + 内容 + 底部浮动栏」，桌面是「左侧常驻侧栏 + 内容」。这一条不改，属于平台差异；要做的是把颜色、圆角、字号、间距、按下反馈对齐，让同一套语言在两个布局里都成立。

## 三、做法与顺序

1. 把 Android 的 `RadiusScale`、`TypeScale`、`SurfaceSpec` 搬到桌面，映射到现有五种 `GlassStyle`，先用同一套数值表
2. 组件化：`SectionHeader`、`ComicCard`、`StateBox`、`LoadMoreFooter` 按 Android 的实现重写，参数取令牌
3. 表面：加发丝描边、上缘高光、按压缩放与阴影阶梯；噪点与背景饱和度在桌面只能近似（没有实时模糊），按现有 `blurWallpaper` 开关决定是否画
4. 逐屏替换，每屏用 xvfb 截图对照

## 四、验收

- 端到端截图：同一页面在 Android 与桌面各截一张，逐项核对圆角、字号、描边、间距
- 代码层面：桌面不再出现写死的圆角与字号常量（除令牌表本身）

## 五、已知约束

- 桌面没有 Android 的实时背景模糊，`Backdrop` 的饱和度与噪点只能近似
- Android 的 `GlassTopBar` 依赖系统状态栏高度，桌面没有对应物
