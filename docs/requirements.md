# 2.2.1 需求（用户口述，2026-10-25 记）

## 一、本地化存储阅读历史与收藏

**目标**：阅读历史与收藏改为**本地持久化**（不再每次依赖服务端拉取），并以此为唯一数据源驱动界面。

**约束与已知边界**：
- **追更做不到**（用户明确：服务端没有稳定的"更新推送/增量"能力，本版不承诺追更）；因此本地存储只管"我读过什么、我收藏了什么"，**不承诺**"知道更新了什么"；
- 服务端数据仍可用于**首次导入/校准**（例如首次登录后把服务端收藏拉下来落本地），但日常以本地为准；
- 需要处理多账号：本地存储必须按账号（或按 uid）隔离，否则换号会串数据。

**新代码、新实现**（不复用现有"每次请求服务端"的路径）：
- 存储层：阅读历史（作品 id、章节 id、页码、时间戳、作品标题/封面快照）；收藏（作品 id、收藏夹归类、收藏时间、标题/封面快照）；
- 迁移：老版本若有服务端拉取缓存，需一次性迁移并把来源标记为 local；
- 一致性：本地写入要能承受进程被杀（按条写入或批量事务），读侧提供"最近 N 条"分页。

**验收（可判定）**：
1. 断网启动 → 历史与收藏**仍可见**（数据来自本地）；
2. 阅读进度更新后立刻杀进程 → 重启后进度不丢；
3. 切换账号 → 两账号的历史与收藏互不干扰；
4. 本地记录条数上限与清理策略明确（例如各 1000 条，按时间淘汰）。

## 二、跟随当前手机壁纸的选项

**目标**：壁纸来源新增"**跟随当前手机壁纸**"一项（Android 读系统壁纸；桌面端不适用或读桌面壁纸需另行评估）。

**实现要点**：
- 取系统壁纸：（注意权限与 API 差异，Android 13+ 有分区存储限制）；
- 壁纸变化监听： 无官方回调，需在**回到前台时**重新读取（/），或提供手动"重新读取"按钮；
- 观感一致性：仍走既有的模糊/压暗/淡化链路（阅读页  与全局  都要覆盖到）；
- 失败退化：读不到壁纸（无权限/系统限制）时**退回主题纯色**，并给出可读提示，不能白屏。

**验收（可判定）**：
1. 选中"跟随手机壁纸"后，应用背景显示为系统壁纸（非应用内图片）；
2. 用户在系统里换壁纸 → 回到应用后背景更新（或点"重新读取"后更新）；
3. 读不到壁纸时不崩、不白屏，退回主题纯色并提示；
4. 与既有壁纸选项（Bing / 二次元 / 自定义 / 纯渐变）互斥且可切回。
