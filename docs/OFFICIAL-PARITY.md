# 与官方客户端的对齐边界

> 这份文档解决一个反复出现的混乱：**"2.1.9" 和 "2.1.12" 到底指谁。**
> 答案：**两套版本号互相独立** —— 我们的发布号（JMNeXt 2.x）与官方的 App 版本号（JMComic3 2.1.x）没有对应关系。

## 一、两套编号，别混

| 编号 | 含义 | 从哪看 |
| --- | --- | --- |
| **JMNeXt 2.1.9 / 2.2.0…** | **我们自己的发布版本** | `app/build.gradle.kts` 的 `versionName`、GitHub Release tag |
| **JMComic3 2.1.9 / 2.1.12…** | **官方客户端版本**，只用于 `Tokenparam` 请求头与服务端校验 | `JmSession.DEFAULT_CLIENT_VERSION` |

所以"2.1.9 的内容"这句话有歧义：
- 若是**我们 2.1.9 发版内容** → 见第二节 B 类（全是我们自己的功能）；
- 若是**官方 2.1.9 的协议变化** → 见第二节 A 类（我们在更早的版本就已对齐，没有单独标注过）。

## 二、四类内容的边界

### A. 官方协议对齐（历史遗留，无版本标记）

这些是"跟着官方实现走"的部分，**早于我们 2.1.9 就已存在**，散落在各文件注释里：

| 位置 | 对齐了什么 |
| --- | --- |
| `JmCrypto.kt` | `Tokenparam: "<秒级时间戳>,<客户端版本>"`、`Token: md5(时间戳 + seed)` |
| `JmSession.kt` | 客户端版本号（服务端校验） |
| `JmHostDiscovery.kt` | 官方构建期注入的域名列表与发现顺序 |
| `JmApi.kt` | 官方 `FormData` 提交形态 |
| `AdBlocker.kt` | 基于对 **JMComic3 v2.1.9** 的审计：广告全部来自两个接口、均为客户端主动请求 |
| `AuthStore.kt` / `SecureStore.kt` | 官方把 JWT 放 Web 存储（1 小时过期）——我们改为 Keystore 加密，**刻意不同** |
| `ReadProgressStore.kt` | 官方进度也只存本地 |

**结论**：A 类不是"某个版本跟的"，而是持续对照的结果；因此**没有"官方 2.1.9 的跟随清单"可列** —— 我们当时没有单独做过一版"跟 2.1.9"的更新。

### B. 我们自己的功能（与官方无关）

**我们 2.1.9 发布的内容全部属于此类**：漫画黑白/墨水屏、阅读页跟随壁纸、壁纸轮换与秒级档位、清缓存、OOM 条带流式反切片。
这些**官方没有**（官方 Web/App 不做图像后处理），不是"跟随更新"，也不应记进对齐清单。

### C. 官方 2.1.12 新增（我们 2.2.0 跟的）

依据：社区库 `hect0x7/JMComic-Crawler-Python` 的 **PR #590（v2.7.10）**，提交信息写明「更新APP版本至2.1.12」。

| # | 官方改动 | 我们原来 | 处理 | 提交 |
| --- | --- | --- | --- | --- |
| 1 | `APP_VERSION` → 2.1.12 | 写死 2.1.9 | 改常量 | `f0020c7` |
| 2 | 用章节 ID 取详情时自动重定向到父本子 | 直接返回那一话（`series` 空、收藏与进度记错 id） | `album()` 加三条守卫的重定向 | `aa30ef4` |
| 3 | 收藏 Toggle 状态不匹配时自动回滚 | **未处理** | **待做** | — |

### D. 官方 2.1.12 里我们**不适用**的

| 官方改动 | 为什么不跟 |
| --- | --- |
| 签到判重（简体中文变体） | 我们**没有签到功能** |
| 图片分割数为 0 时不解码 | 我们 `bands.isEmpty()` 已早返回，**行为等价** |

## 三、以后每次跟进的记录规则（固定五列）

每个跟随项必须能填满这五列，缺一列就不算跟完：

1. **官方版本**（2.1.12 这类，不是我们的发版号）
2. **依据来源**（官方发布说明 / 社区库 PR / 反编译 diff —— 写清是哪个）
3. **我们原来的行为**
4. **是否适用**（适用就改；不适用要写理由，不能空着）
5. **验收方式**（编译 / 单测 / 真机哪一处行为）

## 四、当前状态

- **A 类**：无需清单，属于长期对照；
- **B 类**：我们 2.1.9 的全部内容，与官方无关；
- **C 类**：2/3 完成（第 3 项收藏回滚待做），完成后再发 2.2.0；
- **D 类**：两项不适用，已写明理由。
